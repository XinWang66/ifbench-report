METHODOLOGY
01 / 07

评测背景与方法

本章说明评测对象、指标口径与工程处理方式，为后续排行与类别分析提供可复现的方法学基础。

WHAT IS IT

IFBench 是什么

AllenAI 发表于 NeurIPS 2025 的精确指令遵循基准（arXiv:2507.02833）。测试集含 300 条来自 WildChat 留出集的真实用户 prompt，每条附带 1~3 个可机器验证的新颖约束，共 58 种约束、83 个验证器。

与 IFEval 不同，这些约束对模型是分布外（OOD）的，覆盖 count / format / words / sentence / ratio / repeat / custom 七大类。

METRICS

三层指标口径

主口径为 prompt-level loose accuracy：对回复做去 Markdown 标记等变换后，任一变体通过即算通过，是论文与公开榜单的通用指标。

同时报告 strict（严格匹配）与 instruction-level（约束级）口径作对照，避免单一指标误读。

ENGINEERING

两类工程修复

一是中文 Windows 环境的编码补丁（文件读写显式 UTF-8）；二是网络鲁棒性增强（单请求超时 300→600/900 秒、失败自动重试 3 次、断点续跑识别并重试空回复）。

评分完全复用官方验证器，不影响评分逻辑，横向可比。

CONSTRAINT-LEVEL INSIGHTS
04 / 07

约束级关键发现

类别之下，58 项具体约束的得分差异揭示了更细粒度的模型行为特征。以下四条是最有价值的发现。

FINDING 01

repeat 类内部分化，暴露训练风格差异

repeat_change（复述原文并只做指定修改）四强全部 100%，说明该能力已被头部模型普遍掌握；但 repeat_simple（一字不改地复述）严重分化 —— glm-5.3 拿到 100%，kimi-k3 为 0%。

100%repeat_change · 四强全通过
0%repeat_simple · kimi-k3

一字不改的机械复述反而更难，提示模型在「忠实性 vs 智能改写」的倾向上存在训练风格差异。

FINDING 02

两个全场死穴

「欧洲首都排序」（european_capitals_sort）四强全部 0 分；「比例重叠」（ratio:overlap）四强均仅 8%。这两类约束可作为「当前大模型共性缺口」的直接证据。

0%european_capitals_sort · 四强
8%ratio:overlap · 四强均值

建议将这两条约束直接纳入后续模型迭代的回归测试集。

FINDING 03

Qwen 存在代际倒挂

qwen3.7-max / plus（51.7 / 50.7）整体强于 qwen3.8 全系（40%~48.3）。3.8 系列在 count 与 words 上明显退化 —— qwen3.8-max 的 count:numbers 仅 12.5%，而 qwen3.7-max 为 62.5%。

51.7%qwen3.7-max overall
45.3%qwen3.8-max overall

另有证据显示动态别名存在版本漂移：固定 checkpoint 的 qwen3.8-max-0902（48.3%）高于动态别名 qwen3.8-max（45.3%）。

FINDING 04

DeepSeek 别名映射得到交叉验证

deepseek-chat（45.3%）与明确版本名 deepseek-v4.1-flash-1017（45.0%）分数几乎一致，确认旧别名底层指向 V4.1-Flash 系列。

重跑策略：首轮固定 300 秒超时；第二轮把超时放宽到 600 秒，并对缺失题目自动重试 3 次；第三轮降至 4 并发、超时 900 秒。

最反直觉的结论：头部模型的指令遵循能力在进步，生成延迟却没有跟上。超时集中在要求长输出与精确字符操作的高难度题上，降低并发收效甚微——瓶颈是单请求生成时长，而不是排队。若以「300 题全部按时交卷」衡量，能力最强的 Kimi 反而是可用性最差的；要分数选 Kimi，要可用性选 GLM / MiniMax。

METHOD

评测方法建议

对慢模型评测必须显式设置大超时 + 重试 + 断点续跑，并把空回复从「已完成」中排除，否则分数会系统性虚低 —— 本评测中 MiniMax 首轮带 95 条空回复时得分虚低约 17 分。
